# STEM-Access Preprocessing Pipeline

## Overview

This document describes the complete preprocessing pipeline for making STEM documents accessible.

## Pipeline Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                    User Uploads Document                         │
│                    (PDF or Image)                                │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│              Step 1: Mathpix Conversion                          │
│  • PDF → Structured Markdown via /v3/pdf API                    │
│  • Image → Text via /v3/text API                                │
│  • Extracts: text, tables, equations (as LaTeX)                 │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│         Step 2: Image Extraction & Analysis                      │
│  • Parse markdown for image references                           │
│  • Extract image URLs                                            │
│  • For each image:                                               │
│    - Send to Gemini API                                          │
│    - Generate WCAG-compliant long description                    │
│    - Inject description into markdown                            │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│         Step 3: MathML Conversion                                │
│  • Identify LaTeX expressions in markdown                        │
│  • Convert to MathML using mathjax-node:                         │
│    - Display math: $$ ... $$                                     │
│    - Inline math: $ ... $                                        │
│  • Preserve LaTeX for fallback                                   │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│      Step 4: Accessible HTML Generation                          │
│  • Convert enriched markdown to HTML (marked.js)                 │
│  • Add semantic HTML structure                                   │
│  • Include ARIA labels                                           │
│  • Embed CSS for consistent rendering                            │
│  • Insert image descriptions                                     │
│  • Format MathML properly                                        │
└──────────────────────┬──────────────────────────────────────────┘
                       │
                       ▼
┌─────────────────────────────────────────────────────────────────┐
│                 Output Delivery                                  │
│  • Original Markdown (from Mathpix)                              │
│  • Enriched Markdown (with descriptions)                         │
│  • Accessible HTML (WCAG 2.1 AA compliant)                       │
│  • Metadata (image count, math count, etc.)                      │
└─────────────────────────────────────────────────────────────────┘
```

## API Endpoints

### `/api/preprocess-document` (POST)

**Purpose**: Full STEM-Access preprocessing pipeline

**Request**:
```javascript
FormData {
  file: File,
  format: 'mmd' | 'html',
  generateDescriptions: 'true' | 'false',
  title: string
}
```

**Response**:
```json
{
  "success": true,
  "data": {
    "originalMarkdown": "...",
    "enrichedMarkdown": "...",
    "accessibleHTML": "<!DOCTYPE html>...",
    "images": [
      {
        "altText": "...",
        "url": "...",
        "generatedDescription": "..."
      }
    ],
    "mathConversions": [
      {
        "original": "$$...$$",
        "mathml": "<math>...</math>",
        "latex": "...",
        "display": true
      }
    ],
    "metadata": {
      "processedAt": "2025-10-18T...",
      "imageCount": 3,
      "mathExpressionCount": 12
    }
  }
}
```

## Processing Times

- **Basic PDF (no images)**: 10-15 seconds
- **PDF with 3 images**: 20-25 seconds
- **PDF with 10 images**: 40-50 seconds
- **Image (single page)**: 5-8 seconds

## Accessibility Features

### Image Descriptions
- Generated by Google Gemini 1.5 Flash
- WCAG 2.1 Level AA compliant
- Include:
  - Visual overview
  - Data trends and patterns
  - Specific values and measurements
  - Technical terminology
  - Context-aware descriptions

### MathML
- Screen reader compatible
- Semantic math representation
- Works with NVDA, JAWS, VoiceOver
- Fallback to LaTeX if needed

### HTML Output
- Semantic HTML5 structure
- ARIA labels on tables and figures
- Proper heading hierarchy
- High contrast styling
- Responsive design
- Keyboard navigable

## Dependencies

- Vanilla JavaScript

## Integration with insights-lm-public

This preprocessing engine serves as the **front-end accessibility layer** for insights-lm-public:

1. **Ingestion**: User uploads inaccessible PDF through insights-lm interface
2. **Preprocessing**: Document is routed through this STEM-Access engine
3. **Loading**: Accessible HTML/Markdown is loaded into Supabase/N8N
4. **Interactive Learning**: User can chat with AI about accessible content
5. **Citations**: AI can reference specific equations and charts
6. **Audio**: ElevenLabs generates podcasts from accessible content

## Testing

To test the preprocessing pipeline:

1. Start the server: `npm run dev`
2. Open http://localhost:3000
3. Toggle STEM-Access Mode ON
4. Upload a STEM document (PDF with equations and images)
5. Wait for processing
6. Review:
   - Enriched markdown with descriptions
   - Accessible HTML output
   - Processing metadata
7. Test with screen reader (VoiceOver, NVDA, JAWS)

## Performance Optimization

- **Parallel Processing**: Image descriptions are generated concurrently
- **Caching**: Consider implementing Redis for processed documents
- **CDN**: Serve static assets from CDN
- **Queue System**: Use Bull/Redis for background processing
- **Rate Limiting**: Implement rate limiting for API protection

## Error Handling

The pipeline includes comprehensive error handling:
- Failed Mathpix conversions
- Gemini API timeouts
- Invalid image URLs
- MathML conversion errors
- File cleanup on errors

All errors are logged and returned to the client with helpful messages.
